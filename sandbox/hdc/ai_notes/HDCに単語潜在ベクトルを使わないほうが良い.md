直感的には「意味の近さ（コサイン類似度）をそのまま引き継げるので良くなりそう」に思えますが、実は**そのまま使うとHDCの代数学が破綻して悪化する**という罠があります。

ただし、「HDCの空間へ適切に射影（エンコード）する」というひと手間を挟めば、意図通り「意味の近さ」を保持した強力な文脈ベクトルを作ることができます。

---

### そのまま使うと破綻する理由

Word2Vecなどの埋め込みベクトル（300次元程度の実数値）を直接HDCの演算に持ち込むと、以下の問題が発生します。

1. **「直交性（独立性）」が崩れてクロストーク（混信）が起きる**
* HDCが複数の単語を足し算（重ね合わせ）できるのは、「異なる概念同士は内積がほぼ0（直交）」という数学的前提があるからです。
* Word2Vecは意味の近い単語（「猫」と「犬」など）の内積が $0.7$ や $0.8$ になります。これを足し算やバインド（掛け算）に使うと、ノイズが雪だるま式に蓄積し、過去の文脈から単語を綺麗に取り出せなくなります（容量が激減します）。


2. **次元数が足りない**
* Word2Vecの一般的な次元数（100〜768次元）では、HDCの「足し算しても情報が消えない」という統計的性質（次元の呪いの逆、擬似直交性）が働きません。最低でも数千〜1万次元が必要です。


3. **バインド（要素積）で意味空間が壊れる**
* HDCのバインド（$\times$）は、2値（$+1/-1$）や位相（複素数・円周上）を前提としています。実数値のまま掛けると、スケールが発散またはゼロに収束してしまいます。



---

### 解決策: 意味を保ったまま超次元空間に飛ばす（Locality Sensitive Hashing / Random Projection）

Word2Vecの「意味の近さ」を活かす場合、ランダム射影（Random Projection）を用いて、Word2Vec（低次元実数）を超次元バイポーラベクトル（10,000次元の $\pm 1$）に変換します。

数学的には「コサイン類似度が高い2つのWord2Vecは、射影後のHDC空間でもハミング距離が近くなる」という性質（SimHash / 超平面LSH）を利用します。

```python
import numpy as np

D_W2V = 300     # Word2Vecの次元数
D_HDC = 10000   # HDCの超次元数

# 1. 射影行列（正規分布ランダム）を一度だけ作って固定しておく
# これが「低次元の意味空間」と「超次元空間」の架け橋になる
np.random.seed(42)
PROJECTION_MATRIX = np.random.randn(D_W2V, D_HDC)

def embed_to_hdc(w2v_vector):
    """Word2VecベクトルをHDCバイポーラベクトル（±1）に変換"""
    # 線形射影して符号を取る（超平面のどちら側にあるかで +1 / -1 を決める）
    projected = np.dot(w2v_vector, PROJECTION_MATRIX)
    return np.where(projected >= 0, 1, -1)

```

---

### この変換を入れるとどうなるか？

1. **意味の近さが維持される**
* 「猫」と「犬」のWord2Vecが似ていれば、変換後の10,000次元の $\pm 1$ ベクトルも、8,000ビットくらい同じ値（類似度 $0.6$）になります。
* 「猫」と「宇宙船」のように無関係なら、ランダムに半々（5,000ビット一致、類似度 $0.0$）で直交します。


2. **HDCの文脈保存と意味検索が両立する**
* 過去文脈ベクトル $C_t = \rho(C_{t-1}) + W_t$ を作ったとき、
* **「直前に出た単語は『猫』か？」** にヒットするだけでなく、
* **「直前に出た単語は『犬』のような動物系か？」** にも部分的に反応するようになります。





### まとめ

* **生Word2Vecをそのまま足し引き・シフトする:** ❌ ノイズが多すぎて文脈が潰れる。
* **完全ランダムベクトルを使う:** ⭕ HDCの数学的には最も綺麗に動作するが、単語間の意味の類似度（猫と犬が近いなど）は失われる。
* **Word2Vecをランダム射影で10,000次元バイポーラに変換して使う:** ⭕ **ベストプラクティス**。意味の近さを保ったまま、HDCのシフト演算や重ね合わせが正常に機能します。
