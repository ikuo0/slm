８～１６トークンまでは線形で減少１６～３２まで対数的に減る
３３トークン以降は0.1あたりから3%ずつ減り、128トークンまで入れる

これで、過去の情報も入るので
HDC無しでこれだけで結構いいとこまでいけないか　という実験












この実験は、HDC導入前に試す価値があると思います。

直近のトークンは文法のために強く保持し、遠いトークンは話題を維持するために弱く残すという設計ですね。

現在の32トークン方式で、予想以上に話題の連続性が得られているなら、128トークンまで拡張することで改善する余地があります。

## 想定している重み曲線

例えば、予測位置からの距離を \\(d\\) として、次のような重みを考えられます。

00.30.60.91.21481216202428324048648096112128

提案を具体化した例。1〜16を線形、17〜32を対数減衰、33〜128を毎トークン3%減衰と仮定

この例で33トークン以降を \\(0.1\times0.97^{d-33}\\) とすると、128トークン目の重みは約0.0055になります。

かなり小さいですが、遠距離の情報が完全に消えるわけではありません。

## 気になるのは、遠距離情報の累積です

現在のような重み付き総和方式では、1トークン当たりの重みが小さくても、対象が多数あれば合計への影響は無視できません。

例えば33〜128トークンの96個について、初期重み0.1、毎回3%減衰なら、重みの総和は約3.15です。

つまり、遠距離情報を弱く保持するつもりでも、全体としては意外に大きな影響力を持つ可能性があります。

これは悪いこととは限りません。むしろ「話題を保持する」という目的には適しているかもしれません。

ただし、直近の助詞や動詞の予測を遠距離の名詞群が邪魔する可能性もあります。

## この方式で期待できること

| 評価項目     | 予想            |
| -------- | ------------- |
| 話題の持続    | 改善する可能性が高い    |
| 同じ話題への復帰 | 増える可能性        |
| 局所的な文法   | 維持できるかが重要     |
| 同一語句の反復  | 改善・悪化どちらもあり得る |
| EOS到達率   | 文脈の変化次第       |

一つ、今回の方式にはHDCと異なる特徴があります。

HDCによって過去情報を別の特徴として保持する場合と違い、今回の方式は128トークンすべてを同じ特徴空間に加算することになります。

したがって、情報量が増える一方で、異なる文脈が似た特徴に圧縮される問題も増える可能性があります。

とはいえ、モデルの入力次元やNN構造を変更しないのであれば、今回の実験は純粋に重み関数と参照範囲の効果を比較しやすいです。

私なら、青空文庫追加後に次の順番で比較します。

1. 現行32トークン・既存の重み
2. 32トークン・新しい重み
3. 128トークン・新しい重み
4. 128トークン＋HDC

特に 2と3の比較 が重要です。

重み関数の変更で改善したのか、過去96トークンを追加したことで改善したのかを区別できます。

現在のモデルが単語の関連性をある程度保持できていることを考えると、HDCを使わなくても、128トークンの緩やかな減衰だけで話題の維持が改善する可能性はあります。

ただし、そのためには学習時と推論時の両方で同じ128トークンの特徴生成を使い、再学習する必要があります。
