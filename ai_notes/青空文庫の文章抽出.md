できます。青空文庫は注記の書式が規格化されているため、かなり高い精度で本文だけを抽出できます。

ただし、すべての作品を完全に復元するのは難しいです。特に外字、特殊な組版、古い書式が問題になります。

青空文庫には公式の[注記一覧](https://www.aozora.gr.jp/annotation/?utm_source=chatgpt.com)があり、機械的な変換を前提に書式が定義されています。

## 1. 除去すべき主な記号

| 元データ                    | 処理後                  |
| ----------------------- | -------------------- |
| `漢字《かんじ》`               | `漢字`                 |
| `｜東京《とうきょう》`            | `東京`                 |
| `［＃ここから３字下げ］`           | 削除                   |
| `［＃改ページ］`               | 削除                   |
| `言葉［＃「言葉」に傍点］`          | `言葉`                 |
| `※［＃「木＋靈」、第3水準1-86-29］` | Unicode文字に変換、または代替処理 |

ルビは削除、組版指示は削除、外字は可能なら実際の文字に置き換えるのが基本です。

## 2. Pythonでの簡易クリーニング

まずは正規表現だけでも相当な部分を処理できます。

```
import redef clean_aozora(text: str) -> str:    # 注記を除去（外字も含めて簡易処理）    text = re.sub(r"［＃.*?］", "", text)    # ルビを除去    text = re.sub(r"《[^》]*》", "", text)    # ルビ開始位置マーカーを除去    text = text.replace("｜", "")    # 不要な空行を圧縮    text = re.sub(r"\n{3,}", "\n\n", text)    return text
```

例えば、

```
彼《かれ》は｜東京《とうきょう》へ向かった。
［＃改ページ］
翌朝［＃「翌朝」に傍点］、雨が降っていた。
```

変換後は、

```
彼は東京へ向かった。
翌朝、雨が降っていた。
```

となります。

ただし、このコードは簡易版であり、外字を示す `※` が残ったり、注記内に特殊な記号が含まれる場合があります。

## 3. 冒頭と末尾は別処理

青空文庫では次のような構造が一般的です。

```
作品名
著者名

-------------------------------------------------------
〖テキスト中に現れる記号について〗
...
-------------------------------------------------------

本文開始

...

本文終了

底本：「○○」
入力：○○
校正：○○
青空文庫作成ファイル：
...
```

冒頭は2本目の区切り線まで、末尾は書誌情報の開始位置から削除する方式が使えます。

ただし、すべてのファイルがこの形式とは限りません。本文中の区切り線を誤って削除しないよう、先頭と末尾の構造だけを調べるのが安全です。

## 4. 機械学習用途なら、さらに簡単にできます

現在の独自文章生成モデルへの学習データ追加が目的なら、私は次の方式を推奨します。

1. 冒頭・末尾のメタデータを除去する。
2. ルビと注記を除去する。
3. 外字は可能ならUnicode化する。
4. 変換後に `［＃` や `《` などが残っていないか検査する。
5. 処理に失敗した作品は学習対象から除外する。

重要なのは、全作品を無理に使う必要がないことです。

仮に1万作品のうち数百作品が特殊な書式で正常に処理できなかったとしても、学習データの量は十分に確保できます。

さらに、現在のモデルは単語や共起関係を利用するため、誤った注記が残っていると、それらも単語として学習してしまいます。

そのため、特殊な作品を無理に処理するより、正しく変換できた作品だけを採用する方式が適しています。

なお、より高い忠実度が必要なら、青空文庫のテキストをXHTMLへ変換する既存の処理系を利用し、HTMLから本文テキストを抽出する方法もあります。外字や複雑なルビの扱いでは、単純な正規表現より有利です。
